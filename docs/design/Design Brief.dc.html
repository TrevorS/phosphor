DESIGN BRIEF · V1 · AUGUST 2026

Phosphor

A spiritual successor to Light Table for the age of coding agents, with the terminal as a first-class citizen.

Thesis

Light Table's bet was killing the edit-compile-run loop: inline evaluation, watches, seeing your program's live behavior instead of imagining it. Agents change what "live state" means. The state you need to see is no longer just your code's values — it's what the agent is doing, thinking, and touching in your tree. Phosphor recreates the Light Table moment for that: I can see what my agent is doing to my codebase in real time, the way Light Table let me see what my functions were doing to my data.

The workflow it serves: mostly reading and directing, rarely editing. The user glances at what changed, talks to Claude, occasionally edits by hand. The editor's job is awareness, not gatekeeping — the tree is the truth, the VCS journal is the safety net, and no ceremony stands between the agent and the code.

Core bets

TUI-native, tmux-friendly. It runs in the terminal. The multiplexer is already the window manager developers trust; don't fight it, embed in it. Expected v1 usage: one tmux window for the editor, an adjacent shell alongside. Zellij/wezterm compatibility later; tmux-first is the wedge because that's where agent sessions live today.

Code-first layout. Buffers dominate. The agent transcript is a summonable pane, not the primary surface. Unseen-change markers pull you to files; the code speaks for itself.

Nothing moves unless you asked. The agent writes to disk continuously, but open buffers never update under your cursor. One mental rule, applied everywhere.

No VCS requirement. Works in any directory. jj (or git) is an enhancement — a stronger safety net when present — never a dependency. No feature may assume a repo exists.

Modal editing. Vim habits carry.

Awareness model

Unseen-change markers. The editor tracks which agent changes you haven't looked at, like unread markers. Open a file and modified regions are flagged in the gutter — markers only in v1, no inline provenance. Glance, mark seen, move on. That is review.

Claude declares review blocks. No task model, no watermark, no approve/reject lifecycle. The harness knows where its own seams are: when a coherent block of work is ready, Claude signals it, which surfaces as a grouped set of unseen markers plus a notification. The user reads when they get a chance.

Dirty-state handling. When Claude modifies a file that's open in a buffer, the buffer holds stable and shows a changed-underneath indicator with an offer to refresh. If the user also has unsaved edits, resolution is a manual choice: refresh, or save over — the cheapest honest rule. With jj present, both versions survive in the journal regardless.

Rejection machinery: none. Don't like a change? Edit it, tell Claude, or undo via your VCS. All of these already exist.

Directing model

The :-prompt is the primary gesture. Talking to Claude costs the same as an ex command: a command-line-style prompt available from anywhere. The transcript stays closed unless summoned.

Selections anchor automatically. Visual-select a region and invoke the prompt: the message carries file and range context. Commenting on code is just talking to Claude with spatial context attached — a message that happens to carry an anchor, not a workflow object. No batch-submit, no thread lifecycle.

One session. One Claude Code session per editor per repo in v1. Multi-agent parallelism changes the inbox, the markers, and who owns the tree — deferred deliberately.

V1 scope

  • TUI editor, modal, tmux-friendly
  • One attached Claude Code session; transcript as summonable pane
  • Unseen-change gutter markers + seen-tracking; Claude-signaled review blocks
  • Dirty-state indicator + offer-to-refresh
  • :-prompt to Claude with selection-anchored messages
  • VCS-aware when present (jj first), fully functional without
  • Persistent undo + seen-state persistence on disk (survive restarts)
  • Session protocol: ACP + MCP combo — ACP for the agent session, MCP for editor-facing tools (review-block signals, notifications)

V1.5

  • Agent-scriptable workspace — editor internals legible to the agent; say a sentence and Claude writes a pane into existence. The extension language's real audience is Claude, not the user.
  • Built-in tmux support — spawning/adopting panes, layout integration. V1 is tmux-friendly; v1.5 makes it tmux-native.

Decided since (design passes 2–9)

  • Name: Phosphor. Leader key: SPC, alongside full ex commands.
  • Theme: the original "phosphor" palette (dark + light) is the v1 default; themes ship base16-style, Catppuccin and Ayu as the first two mappings. Hue is the contract — green always means Claude.
  • Architecture: tree-sitter + LSP + ACP + MCP feed one semantic store; every surface (markers, anchors, watches, inbox, pickers) is a query over it. Widgets are pure renderers over a ViewModel; key → Action → store.
  • Anchors bind to tree-sitter nodes, not lines — threads, seen-state, and watches survive rewrites (promoted from the cut list).
  • Lineage: Emacs and Light Table, not vim — Rust is the C core; the editor layer itself ships as Steel in the source tree, redefinable live from the REPL. First-class languages are a curated set (TS, JS, Rust, Python, Steel, Markdown, JSON, CSV + TOML/YAML/HTML/CSS); everything else is honest plain text where the full agent loop still works, with define-language as the userspace road up.
  • Scripting: Steel — one scheme dialect for config, the live REPL, and (v1.5) Claude-built panes. Vim grammar extends with agent nouns: viu, sib, dih, :'<,'>c.
  • Inbox and watches are v1 surfaces: the inbox is one list of everything Claude said (severity = one MCP flag; unread = unseen); watches stream values from real runs as virtual text — the Light Table inheritance.
  • Chrome is three strips: tab bar (2+ panes only), statusline (never wraps; sheds right-to-left at narrow widths), tmux below. UI keyhints spell full commands (:reattach, never :ca).
  • Interaction rules: at most one float focused, needs-you never steals focus, esc pauses Claude at tool boundaries (steer / resume / abort), permission always-allow writes a legible rule to init.scm, large review blocks group by directory with Claude's annotations.

Cut from v1 (Beyond)

  • Review ceremony — approve/reject gates, ready-states, watermarks. Process for teams that don't trust each other; layered on later by users who want it.
  • Provenance-on-keypress — the transcript excerpt that produced an edit, foldable at the marker. A strong v1.5 candidate now that the store tracks provenance anyway.
  • Multi-session / parallel agents
