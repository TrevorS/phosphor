Ratatui component breakdown

Crate layout, buy-vs-build calls on the ratatui ecosystem, and the custom widget specs — companion to the Design Brief and Design Language v0.2.

Crate layout

crateowns
phosphorthe binary: event loop, terminal setup, config load, session bootstrap
phosphor-corethe semantic store: regions, seen-state, anchors, threads, watches, inbox, review blocks; persistence (undo history + seen-state on disk); no UI deps
phosphor-buffertext engine: rope, edits, persistent undo, tree-sitter parse + highlight, LSP client state
phosphor-uithe substrate widgets below — pure renderers; depends on ratatui-core + phosphor-core ViewModels only
phosphor-agentACP session client, MCP server (editor tools exposed to claude), transcript model
phosphor-steelSteel embedding: the runtime, the Action/query bindings (same vocabulary MCP exposes), REPL
phosphor-vcsoptional jj/git adapters behind a trait; compiled in, activated on detection
runtime/*.scmnot a crate — the editor layer, in Steel, shipped in the source tree: keymaps + leader tree, picker sources, statusline segment order, permission rules, float layouts, define-language calls for the first-class set

Dependency rule mirrors the design language and the Emacs architecture: widgets are pure renderers, policy is Steel. phosphor-ui reads ViewModels derived from phosphor-core, never mutates. Input maps key → Action; Actions mutate the store; the store re-derives. The Rust crates are the C core; runtime/*.scm is the editor, and Steel, MCP, and the CLI call the same Action API — which is what makes the workspace scriptable by you, your shell, and claude alike.

Platform layer

  • ratatui 0.30+ workspace — depend on ratatui in the app; phosphor-ui depends on ratatui-core only, per the modular split, so it stays a lean widget library.
  • crossterm backend — with the kitty keyboard protocol enabled for real modifier chords, synchronized output wrapping every frame (torn frame = P0), OSC 8 hyperlinks for transcript jump-links, undercurl via escape passthrough with underline fallback.
  • ropey — rope text buffer; the same choice ratatui-code-editor validates.
  • tree-sitter — incremental parsing; node ids are the anchor substrate, highlight queries drive syntax color. Grammars bundled for the first-class set (TypeScript, JavaScript, Rust, Python, Steel, Markdown, JSON, CSV, TOML, YAML, HTML, CSS); loadable as dylibs via define-language beyond it.
  • steel-core — the embedded scheme that IS the editor layer: config, REPL, and everything in runtime/*.scm.

Buy, fork, or build — the ecosystem calls

Posture: buy first. Custom code is reserved for the two things that are the product — the semantic store and the gutter/virtual-text contract. Where a buy covers 80%, wrap and restyle rather than rebuild.

Custom widgets — phosphor-ui

Reading order for implementation. Each lists its ViewModel input and key states; all take &Theme.

Theme

Actor/state palette struct: claude, you, attention, trouble, transient, steel + neutral ramp + syntax map. Loaded from base16-style files; phosphor dark/light built in, Catppuccin and Ayu ship as mappings. Validation: a theme that reassigns actor hues is rejected at load.

BufferView (ratatui-code-editor core + phosphor layer)

The bought editor owns text rendering, highlighting, cursor, selection, and edit history. The phosphor layer wraps it with the 3-column contract (1-cell state bar → line numbers → text), region tints + undercurl via its marks API, interleaved virtual-text rows (┊-prefixed, owned by a region id: threads, watches, diagnostics, hints), soft-wrap ↪ continuations (no line number), fold rows (▸⋯ n lines), insert-only trailing-whitespace marks. Never scrolls under the user — "nothing moves unless you asked" is enforced in this wrapper.

GutterBar

The 1-cell state column, resolved per row from Vec<RegionState> with priority trouble > attention > claude-unseen > none. Degrades to ▎ on non-truecolor terminals.

StatusLine

Mode chip + file/dirty + spring + SessionState + counters, segments joined by │. SessionState is ONE enum (Idle, Working{elapsed}, Waiting, Paused, Lost, None) rendered identically everywhere it appears. The widget renders and truncates; the segment list, order, and shed priority (counters → jj → cursor pos → session prose → mode word; ✻/●n last) come from Steel — redefine a segment in the REPL and the next frame has it. Never wraps — a second line is a bug, enforced by truncation in the widget.

TabBar

Appears at 2+ panes. Flat vim-style: active tab = 2px actor-colored top rule + bright text; inactive = meta-gray; per-tab unseen counts (●n). Input: Vec<TabVM { title, kind, unseen }>.

Float

The one chrome primitive: Block wrapper enforcing header / body / footer and mood border (informational #2a5c44, needs-you #6b5426 + dark-amber body, passive #2a3c2e no-footer). Enforces the one-float rule (opening replaces), full-width under 100 cols, background dim to the theme's behind color. Bodies plug in: Picker, DiffBody, QuestionBody, HelpGrid, ArchDiagram.

Picker (nucleo engine)

Filter line (tui-textarea) + nucleo matcher worker + list + optional preview split (dropped under 100 cols). One widget, many sources — and sources are Steel: unseen regions, files (with agent activity columns), inbox, grep/symbols (tab cycles source), session adoption, jj timeline all ship as (define-picker-source ...) in runtime/, so adding one is userspace. nucleo streams items and matches off-thread; match-highlight indices color the rows. List rows are Vec<Span> so agent context (● counts, ✻ activity, seen ✓) renders in actor colors. Selection → Action, never direct mutation.

DiffBody (ratatui-code-editor diff view + phosphor layer)

The bought diff view (added/deleted lines, expandable unchanged sections) restyled; phosphor adds per-hunk seen state, directory grouping via tui-tree-widget, and claude's group annotations as meta text. Used by: review block, hunk peek, :diff-disk (three-exit footer).

QuestionBody

Needs-input and permission asks: prose, amber digit options [1]–[n], full-command footer. Never steals focus — renders alongside a waiting statusline flag; digits only answer while it's focused. Always-allow answers emit a Steel rule write.

TranscriptPane

A pane, not a float. Turn list: prompt lines (claude-green ❯), prose, tool rows (▸ verb file ±counts — OSC 8 jump links), seam markers (⏸ paused, ✕ lost), review-ready lines. Folds by turn at scale. Streams during Working; input line docks at bottom when focused.

PromptLine

The : line at screen bottom; ⚓ anchor chip prefix when a selection rides along; ex-style history (q: integration); routes to command parse or claude message.

KeymapFooter / WhichKey

Same data, two densities: float footers (verb-labeled, primary first, esc last) and the SPC leader grid. Fed from the live keymap so Steel rebinds appear automatically. Also owns the once-per-session unknown-key hint.

WatchOverlay

Virtual-text value streams: ◉ ⇒ sequences with run provenance line. Values arrive over the session/MCP from real executions; renders through BufferView's virtual-text rows — this widget only formats.

Event & data flow

  • Input: crossterm event → edtui KeyEventHandler (operator-pending, counts, registers; agent nouns u/h/t/b registered as custom text objects) → Action. The Action layer isolates the handler so it stays replaceable if the grammar outgrows it.
  • Actions are the single mutation API: buffer edits, seen marks, session messages, float open/close. Steel and MCP invoke the same enum.
  • Store → ViewModel: after each Action batch (or ACP/LSP event), dirty ViewModels re-derive; one draw call renders the frame inside a synchronized-output block.
  • Async: tokio; ACP stream, LSP, tree-sitter re-parse, and VCS polls post events into the same queue as input — no widget ever blocks.

Philosophy — languages, scripting, and the Rust–Steel barrier

The design lineage is Emacs and Light Table, not vim: a small compiled core under a live, self-modifying editor. Vim gave us the grammar; Emacs gives us the architecture.

Language support: first-class citizens, and an honest second tier

First-class languages are a curated, opinionated set: TypeScript, JavaScript, Rust, Python, Steel, Markdown, JSON, CSV, plus the config dialects agents live in (TOML, YAML) and the web substrate (HTML, CSS). First-class means the full promise, tuned by hand: bundled grammar, blessed LSP auto-configured (not just discovered), watch-expression shapes that actually work, test-runner integration for review blocks, structural text objects verified against real code, and CSV/Markdown getting bespoke surfaces (virtual column alignment, live preview) rather than generic buffer treatment. These are the languages phosphor is for — the agent-era working set — and each one is a maintained product commitment, which is exactly why the list is short.

Everything else is second tier, and the tier is honest: plain text with line-based regions. Unseen markers, review blocks, the inbox, the transcript, dirty-state — the entire agent loop — work on any file, because they're store features, not language features. What second tier lacks is node anchoring (anchors fall back to line+content matching), structural text objects, and watches. There is no in-between: we do not ship half-tuned grammars that anchor wrongly and erode trust in the anchor promise. The road up is Steel — (define-language ...) declares a grammar, an LSP command, and locale hooks, and a second-tier language becomes first-class in userspace; the bundled set is just the define-language calls we wrote and stand behind.

Push Rust down: the editor is written in its own extension language

The Emacs lesson, taken literally: Rust is the C core, Steel is the editor. Rust owns the substrate that must be fast and crash-free — the rope, tree-sitter, transports (LSP/ACP/MCP), the semantic store, the renderer, the raw input decoder. Everything above that line is Steel that ships with the editor: the keymaps and leader tree, the pickers' sources and columns, the statusline segments, float layouts, the inbox, permission rules, which-key, even the :arch diagram. Not "configurable via Steel" — implemented in Steel, readable in the source tree, redefinable at runtime. :describe-key on any binding jumps to the scheme that implements it, Emacs-style. The placement test: "would two reasonable users want this to differ?" → Steel; "can this corrupt a buffer or drop a frame?" → Rust. When in doubt, push down later — promoting hot Steel to Rust is an optimization; excavating baked-in Rust into Steel is a rewrite.

The live surface: REPL-driven editing of the editor

The Light Table inheritance applied to phosphor itself: the editor is a running image you reshape while using it. The Steel REPL isn't a debugging tool bolted on — it's the primary extension workflow. Evaluate (keymap-set! ...) and the binding is live and which-key knows it; redefine a picker source and the open picker re-derives; (watch-place ...) from the REPL and the buffer sprouts virtual text. Surface changes never require restart — init.scm is just the REPL session that runs at boot, and anything you evaluate can be persisted back to it with one command. Safety comes from the barrier, not from ceremony: Steel can only emit Actions and read ViewModels, so live redefinition can misconfigure but never corrupt a buffer, and a broken init.scm boots the editor anyway with the error in a float. This is also, unchanged, the v1.5 agent story — claude scripting a pane into existence is a REPL session with a different author. One API, three doors (Steel in-process, MCP for agents, phosphor --eval for the shell); the doors differ in transport, never in vocabulary.

Build order

Steel is step 2, not step 7 — the Emacs architecture only holds if the editor layer grows up in scheme from the start; retrofitting policy out of Rust is the rewrite we swore off.

  1. Theme + ratatui-code-editor integration + StatusLine shell — phosphor renders and edits a file with highlighting on day one; feels like the mockups
  2. Steel runtime + Action/query bindings + REPL — from here on, every keymap, segment, and picker source lands in runtime/*.scm, not Rust
  3. edtui input handler wired to Actions + persistent undo + the gutter/virtual-text layer (plain editor complete: 7c) · keymaps in Steel, WhichKey reads them (3c, 6d)
  4. LSP (completion float via passive Float) — highlighting already bought
  5. semantic store + GutterBar + seen-tracking + Picker with Steel sources (unseen/files) — the awareness loop (1a, 2a, 3d)
  6. ACP session + MCP tool surface + TranscriptPane + PromptLine + QuestionBody — the directing loop (1b, 1c, 4a, 7a, 7e)
  7. DiffBody + review blocks + inbox (2b, 4b, 5c) · dirty-state + :diff-disk (1d, 5b) · jj adapter + timeline (3b)
  8. watches (5a) — last, it rides on everything above
