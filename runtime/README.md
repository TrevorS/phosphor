# `runtime/` — the editor layer

Not a crate. This is the Steel source tree: the editor itself, as opposed to the core
that hosts it (invariant 1 — Rust is the C, `runtime/*.scm` is the lisp, redefinable
from a live REPL).

What lands here, and when:

| Path | Contents | Task |
|---|---|---|
| `init.scm` | boot: load order, defaults | T021 |
| `keymaps.scm` | the live table, `keymap-set!`, key dispatch; then every binding, with counts and named registers | T022, then T033 |
| `statusline.scm` | the whole statusline: which segments, in what order, joined how, and the shed ladder | T025 |
| `repl.scm` | which forms the REPL persists, and where | T022 |
| `persisted.scm` | what the REPL wrote down; loads last | T022 |
| `pickers/` | picker sources and columns | `store` |
| `permissions.scm`, `inbox.scm`, `watch.scm` | the directing surfaces | `agent` |

Placement test: *would two reasonable users want this to differ?* → here. *Can it
corrupt a buffer or drop a frame?* → Rust.

Steel composes primitives; it never defines them, and it never calls ratatui. It
returns a declarative view tree that `phosphor-ui` interprets (Q12).

## The view tree, as this tree writes it

One constructor per node kind, named `view/<tag>` — `view/line`, `view/mode-chip`,
`view/spans` — **generated from the protocol itself** (`phosphor-steel/src/view.rs`
walks `phosphor_core::view`'s declared union). There is no list of node kinds in any
`.scm` file, because a list here would rot the first time one is added.

Three things follow, and each is checked by a test rather than promised:

- an argument is validated at the form that wrote it, so a misspelled tone names the
  constructor and the field rather than failing three layers up;
- an absent optional is `void`, not `#false` — `#false` is a value the protocol would
  try to decode;
- `view/spans` is the one escape hatch (T080): rows of styled runs, for a surface no
  primitive covers. It is generated by the same loop as everything else, so it is a
  node kind rather than a privileged path, and `scripts/lint-one-escape-hatch.sh`
  fails if a second node kind ever grows the same shape.

## Boot

`init.scm` is the only file the host loads by name. Everything else is named by it, in
the list it binds to `phosphor/boot-files`, which Rust reads *after* the last form of
`init.scm` has run and then loads in order.

The order is data rather than a `(load …)` call because a binding that loaded a file
would be re-entering the VM that is currently running it. Reading a declared list
afterwards gets the same redefinability with no re-entrancy — and it survives a broken
form, since a `define` that ran is one Rust can read even if the form beside it failed.

**Each top-level form runs on its own.** A form that fails is dropped, named in the boot
float with its file and line, and the forms around it still run; likewise each file in
the load order is independent of the others. So a stray paren costs you one form, not the
editor — which is `T021`'s acceptance criterion, checked in
`crates/phosphor-steel/tests/broken_init.rs` against this very tree with a mistake
planted in it.

One limit worth knowing: an unclosed `(` is not a broken form, it is a form that has not
finished, so everything after it is *inside* it and goes down with it. The float names
the line it opened on.

## The keymap is live because it is only here

`keymaps.scm` holds the table and the dispatcher; **Rust holds no copy of either**. On
every keystroke the host spells the whole unfinished sequence in vim notation and calls
`(phosphor/resolve scope keys)`, which answers a **role** — `(motion "word-forward")`, the
data the input machine composes with — or `'ran` for a thunk it ran itself, or `'pending`,
or `'unbound`. So a `(keymap-set! …)` typed at `:repl` is in force on the next key with no
reload step and no invalidation to forget. That is `T022`'s liveness claim, and it is a
property of where the table lives rather than a feature that had to be built.

The dispatcher is **stateless**: the machine already holds the half-typed sequence and
hands the whole of it over, so `]` answers `'pending` while `]u` is bound without the layer
remembering anything. `T022`'s `phosphor/press` — which answered `'handled` and kept its own
copy of the pending keys — is gone; two copies of one sequence could only disagree.

Two parsers meet here and neither may drift: `phosphor/keys` folds what a *person* wrote
into the canonical spelling, and `Key::notation` spells what a *terminal* sent. `<C-K>`,
`<S-C-k>` and `<c-k>` are one chord and one binding, spelled `<C-S-k>`, because the machine
only ever asks with that one — `crates/phosphor-steel/tests/no_bindings_in_rust.rs` drives
the fold from both ends.

The ex line is scheme all the way down, including its **range**: `:'<,'>c` is the command
`c` over the selection, and `:12,20c` selects those lines before it acts. `phosphor/ex`
reads the range off the front and a command asks for it with `(ex-range)`.

## The statusline is composed here, not drawn here

`statusline.scm` binds `phosphor/status-line`. Rust hands it one hash — what is true
right now: mode, file, session, counters, cursor, the keys this surface teaches — and it
answers a view tree. Which segments exist, what order they sit in, what joins them, and
which of them are given up first when the terminal is narrow are **all** in that file;
`crates/phosphor-steel/src/status.rs` is the ViewModel and the call, and has no segment
list, no order and no ladder in it.

Three setters change it live, and they are `set!`s rather than `define`s for a reason
worth knowing: a top-level `define` of a name that already exists binds it for forms
compiled *after* it, and the composition is already compiled — so it would go on reading
the old one. Mutating the table the composition reads every frame is what makes the next
frame have it, which is the same reason `keymap-set!` mutates.

| form | changes |
|---|---|
| `(status-set! 'chip (lambda (vm) …))` | one segment |
| `(status-order-set! 'right '(session counters))` | which segments, in what order |
| `(status-ladder-set! '(counter-words vcs …))` | what is given up first (§11) |

All three are in `repl.scm`'s persistent heads, so a statusline you rearranged at `:repl`
is still yours after a restart. `phosphor/status-line` itself is the exception to the
`set!` rule — Rust asks for it by name on every composition, so redefining *it* takes
effect immediately, and a whole statusline of your own is one form.

## What the REPL persists, and where

`repl.scm` binds `phosphor/persistent-heads`. A form typed at `:repl` whose head is in
that list is appended after it runs — `6b`'s `⇒ #ok · persisted to …`; a form whose head
is not is session-only. **The REPL persists, not `keymap-set!`**: only the REPL has the
source text (a closure cannot be printed back as the form that made it), and a form
loaded at boot must not append itself to the file it came from.

**It is not written to `init.scm`, and the reason is the boot order above.** `init.scm`
runs to its last form *before* Rust reads the load order it declared, so a form appended
there can only use names Rust registered — `(keymap-set! …)` is defined in `keymaps.scm`,
which has not loaded yet, and a persisted rebind comes back on the next start as a
free-identifier fault in a boot float. That is not a hypothetical: it is what the first
run of this feature did.

So `repl.scm` binds `phosphor/persist-file` to the file that loads **last**
(`persisted.scm`), where everything a persisted form could depend on is already defined.
A layer that declares no such file gets `init.scm`, which is right for a one-file layer
and is what `6b` draws. The regression is
`crates/phosphor/src/main.rs`'s `a_persisted_rebind_survives_the_next_boot`, which types a
rebind, throws the editor away, and starts another one over the same tree.

## Where this tree is read from

`Runtime::root()` takes the first of:

1. `$PHOSPHOR_RUNTIME`, taken at its word;
2. `$XDG_CONFIG_HOME/phosphor` (or `~/.config/phosphor`) containing an `init.scm`;
3. `./runtime` containing an `init.scm` — the checkout, so `cargo run` in the repo boots
   the layer you are editing.

**Open, and flagged rather than decided:** whether a shipped layer and a user's own layer
are two trees that both load, and which one `persist-form` appends to (`6b`'s *"persisted
to init.scm"*, `7a`'s always-allow rule). Today there is one tree.
